2. Requisitos

MySQL 5.7 acepta esas restricciones pero no las aplica (se aplican desde MySQL 8.0.16; MariaDB las aplica desde la versión 10.2). Además, MySQL 5.7 dejó de recibir actualizaciones en octubre de 2023.

3. Instalación para probar en un equipo (XAMPP)

Este camino sirve para revisar la solución en un equipo con Windows. Si ya tiene XAMPP instalado, empiece en el paso 2.

1
Instalar XAMPP

Descargar XAMPP para Windows desde https://www.apachefriends.org (una versión con PHP 8.1 o superior) e instalarlo con las opciones por defecto en C:\xampp.

2
Iniciar Apache y MySQL

Abrir el XAMPP Control Panel y pulsar Start en Apache y en MySQL. Los dos nombres deben quedar con fondo verde.

3
Copiar la aplicación

Descomprimir teatro.zip (o copiar la carpeta teatro) dentro de C:\xampp\htdocs\. Debe quedar así:

C:\xampp\htdocs\teatro\index.php
C:\xampp\htdocs\teatro\comprar.php
C:\xampp\htdocs\teatro\database\teatro.sql
...

Si al descomprimir queda una carpeta dentro de otra (htdocs\teatro\teatro\index.php), mueva la interior un nivel arriba.

4
Restaurar la base de datos con phpMyAdmin
  1. Abrir http://localhost/phpmyadmin en el navegador.
  2. Pulsar la pestaña Importar (arriba).
  3. En Archivo a importar, pulsar Seleccionar archivo y elegir C:\xampp\htdocs\teatro\database\teatro.sql.
  4. Dejar el resto de opciones como están y pulsar Importar (o Continuar), al final de la página.

Resultado esperado: un mensaje verde de importación exitosa y, en la columna de la izquierda, la base teatro con las tablas obra y ventas.

No hace falta crear la base antes: el script la crea. En Windows, MariaDB muestra los nombres en minúsculas; la aplicación funciona igual.

5
(Alternativa al paso 4) Restaurar desde la consola

Abrir el Símbolo del sistema (CMD, no PowerShell) y ejecutar:

C:\xampp\mysql\bin\mysql.exe -u root < C:\xampp\htdocs\teatro\database\teatro.sql

Si su usuario root tiene contraseña, agregue -p y escríbala cuando la pida.

6
Configurar la conexión (solo si root tiene contraseña)

La aplicación se conecta a localhost:3306 con el usuario root sin contraseña, que es lo que trae XAMPP. Si no cambió esa contraseña, salte este paso. Si la cambió:

  1. Copiar includes\config.local.example.php con el nombre includes\config.local.php.
  2. Abrirlo con el Bloc de notas y escribir la contraseña:
return [
    'db' => [
        'host'     => 'localhost',
        'port'     => 3306,
        'user'     => 'root',
        'password' => 'su_contraseña',
    ],
];
7
Abrir la aplicación

Ir a http://localhost/teatro/.

Resultado esperado: la página «Obras disponibles» con 5 obras.

8
Comprobar que los archivos internos están protegidos

Abrir http://localhost/teatro/database/teatro.sql y http://localhost/teatro/includes/config.php.

Resultado esperado: «Forbidden» / «Acceso prohibido» (error 403) en los dos.

XAMPP aplica los archivos .htaccess que traen las carpetas includes/, database/ y docker/.

4. Producción con Docker (recomendada)

Con Docker, un solo comando levanta tres servicios ya configurados para producción: el servidor web (Nginx), PHP y MySQL. No hace falta instalar ni configurar PHP, MySQL ni Apache en el servidor.

Qué queda funcionando

ServicioQué hace
web (Nginx)Es lo único accesible desde fuera (puerto 8080 por defecto). Solo ejecuta las cuatro páginas públicas y sirve la hoja de estilos; cualquier otra ruta (includes/, database/, .env…) responde 404. Limita las solicitudes por IP.
php (PHP 8.5-FPM)Configuración de producción: los errores van al log, nunca a la pantalla. Sistema de archivos de solo lectura.
db (MySQL 8.4)Sin puertos publicados: solo el servicio php puede conectarse, por una red interna sin salida a Internet. La aplicación usa el usuario teatro_app, que solo puede leer, insertar, actualizar y borrar filas de TEATRO. La contraseña de root es aleatoria.

Los tres servicios se reinician solos si fallan o si se reinicia el servidor. Los datos se guardan en un volumen de Docker y se conservan entre reinicios.

4.1 Instalar Docker (si el servidor no lo tiene)

SistemaCómo
Ubuntu 22.04 o 24.04sudo apt update && sudo apt install -y docker.io docker-compose-v2
Otras distribuciones LinuxSeguir https://docs.docker.com/engine/install/
Windows o macOSInstalar Docker Desktop desde https://www.docker.com/products/docker-desktop/ y abrirlo.

Para comprobar la instalación: docker compose version debe mostrar una versión.

4.2 Levantar la aplicación

1
Copiar la aplicación al servidor

Por ejemplo, en /opt/teatro. Desde el equipo donde está el ZIP:

scp teatro.zip usuario@IP_DEL_SERVIDOR:/tmp/
ssh usuario@IP_DEL_SERVIDOR
sudo apt install -y unzip
sudo unzip /tmp/teatro.zip -d /opt/        # crea /opt/teatro
2
Revisar la configuración (recomendado)
cd /opt/teatro
sudo cp .env.example .env
sudo nano .env

Cambie al menos TEATRO_DB_PASSWORD por una clave propia (solo letras, números, puntos y guiones). Las demás opciones están explicadas en la sección 8. Hágalo antes del paso 3: la clave se fija la primera vez que se crea la base.

3
Levantar los servicios
cd /opt/teatro
sudo docker compose up -d

La primera vez tarda uno o dos minutos: descarga las imágenes, prepara PHP, crea la base TEATRO e importa database/teatro.sql.

4
Comprobar que está en marcha
sudo docker compose ps

Resultado esperado: los servicios web, php y db en estado «running» o «Up», y db como «healthy».

5
Abrir el puerto en el cortafuegos (si lo hay)
sudo ufw allow 8080/tcp
6
Abrir la aplicación

Ir a http://IP_DEL_SERVIDOR:8080/ (o http://localhost:8080/ si Docker está en el mismo equipo).

Resultado esperado: «Obras disponibles» con 5 obras. Y http://IP_DEL_SERVIDOR:8080/database/teatro.sql responde «404 Not Found».

Si en la carpeta existe includes/config.local.php (por ejemplo, de una prueba anterior con XAMPP), bórrelo: tiene prioridad sobre la configuración de Docker y haría que la aplicación busque MySQL en otro lugar.

4.3 Publicarla con un dominio y HTTPS

Para producción real conviene un dominio con certificado HTTPS. La forma más simple es poner Caddy delante, que obtiene y renueva el certificado solo:

  1. Apuntar el dominio (por ejemplo, teatro.ejemplo.com) a la IP del servidor, con un registro DNS de tipo A.
  2. Hacer que el puerto 8080 solo se escuche dentro del servidor: en .env, poner TEATRO_PUERTO=127.0.0.1:8080 y aplicar con sudo docker compose up -d.
  3. Instalar Caddy y configurarlo:
sudo apt install -y caddy        # si apt no lo encuentra: https://caddyserver.com/docs/install
sudo nano /etc/caddy/Caddyfile

Reemplazar el contenido por:

teatro.ejemplo.com {
    reverse_proxy 127.0.0.1:8080
}
sudo systemctl reload caddy
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw delete allow 8080/tcp      # el 8080 ya no se usa desde fuera

Al abrir https://teatro.ejemplo.com se verá la aplicación con candado. La aplicación reconoce el HTTPS por el encabezado X-Forwarded-Proto que envía el proxy, y marca la cookie de sesión como Secure. Nginx, dentro de Docker, toma la IP real del visitante de X-Forwarded-For, para que los límites por IP se apliquen a cada visitante y no al proxy. Si ya usa Nginx o Apache como proxy, sirve igual: deben reenviar a http://127.0.0.1:8080 con esos dos encabezados.

5. Producción en un servidor Linux con Apache o Nginx

Para un servidor que ya tiene (o tendrá) PHP y MySQL instalados directamente. Los ejemplos son para Ubuntu 22.04 o 24.04; en Debian, cambie mysql-server por mariadb-server.

5.1 Pasos comunes

1
Instalar los paquetes
# Con Apache:
sudo apt update && sudo apt install -y apache2 php libapache2-mod-php php-mysql mysql-server unzip
# Con Nginx:
sudo apt update && sudo apt install -y nginx php-fpm php-mysql mysql-server unzip

Comprobar que PHP es 8.1 o superior con php -v.

2
Copiar la aplicación
# Apache: /var/www/html/teatro  (se abrirá en http://servidor/teatro/)
sudo unzip /tmp/teatro.zip -d /var/www/html/
# Nginx: /var/www/teatro  (se abrirá en la raíz del dominio)
sudo unzip /tmp/teatro.zip -d /var/www/

Los archivos pueden quedar con dueño root: el servidor web solo necesita leerlos.

3
Restaurar la base de datos
sudo mysql < /var/www/html/teatro/database/teatro.sql     # o /var/www/teatro/... con Nginx
4
Crear el usuario de la aplicación con permisos mínimos

En producción la aplicación no debe usar root. Este usuario solo puede leer, insertar, actualizar y borrar filas de TEATRO:

sudo mysql -e "CREATE USER 'teatro_app'@'localhost' IDENTIFIED BY 'una_clave_segura';
               GRANT SELECT, INSERT, UPDATE, DELETE ON TEATRO.* TO 'teatro_app'@'localhost';"
5
Configurar la conexión
cd /var/www/html/teatro        # o /var/www/teatro con Nginx
sudo cp includes/config.local.example.php includes/config.local.php
sudo nano includes/config.local.php   # 'user' => 'teatro_app', 'password' => 'una_clave_segura'
sudo chown root:www-data includes/config.local.php
sudo chmod 640 includes/config.local.php   # solo el servidor web puede leer la clave

5.2 Con Apache

6
Bloquear las carpetas internas

Ubuntu y Debian ignoran los archivos .htaccess por defecto (AllowOverride None), así que el bloqueo se hace en la configuración de Apache. Crear el archivo:

sudo nano /etc/apache2/conf-available/teatro.conf

con este contenido:

<DirectoryMatch "^/var/www/html/teatro/(includes|database|docker)(/|$)">
    Require all denied
</DirectoryMatch>
<FilesMatch "^(\.env.*|docker-compose\.yml|.*\.md)$">
    Require all denied
</FilesMatch>

Activarlo y comprobar:

sudo a2enconf teatro && sudo systemctl reload apache2
curl -I http://localhost/teatro/database/teatro.sql

Resultado esperado: HTTP/1.1 403 Forbidden.

7
HTTPS con un dominio
sudo apt install -y certbot python3-certbot-apache
sudo certbot --apache

Certbot pide el dominio, obtiene el certificado y configura la redirección a HTTPS. La renovación es automática.

8
Solo si Apache está detrás de un proxy o balanceador

Para que los límites por IP vean la IP real del visitante y no la del proxy, activar mod_remoteip indicando la IP del proxy (aquí, 10.0.0.5 como ejemplo):

sudo a2enmod remoteip
printf 'RemoteIPHeader X-Forwarded-For\nRemoteIPTrustedProxy 10.0.0.5\n' | sudo tee /etc/apache2/conf-available/remoteip.conf
sudo a2enconf remoteip && sudo systemctl reload apache2

El HTTPS detrás del proxy se detecta solo (encabezados X-Forwarded-Proto o Forwarded).

La aplicación queda en https://dominio/teatro/ (o http://IP_DEL_SERVIDOR/teatro/ sin dominio).

5.3 Con Nginx y PHP-FPM

Con Nginx no se usan los .htaccess. La configuración siguiente es una lista de lo único que se puede abrir; todo lo demás no existe para el navegador.

6
Crear el sitio
ls /run/php/                     # anote el nombre del socket, por ejemplo php8.3-fpm.sock
sudo nano /etc/nginx/sites-available/teatro
server {
    listen 80;
    server_name teatro.ejemplo.com;
    root /var/www/teatro;

    # Solo se ejecutan las páginas públicas.
    location ~ ^/(index|comprar|confirmacion|consultar)\.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;    # el socket anotado arriba
    }

    location ^~ /assets/ { try_files $uri =404; }
    location = / { rewrite ^ /index.php last; }

    # Todo lo demás (includes/, database/, docker/, .env...) responde 404.
    location / { return 404; }
}
sudo ln -s /etc/nginx/sites-available/teatro /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default      # si este servidor es solo para Teatro
sudo nginx -t && sudo systemctl reload nginx
curl -I http://localhost/database/teatro.sql

Resultado esperado: nginx -t dice «syntax is ok» y la última línea muestra HTTP/1.1 404 Not Found.

7
HTTPS con un dominio
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx

7.6 Lo que no se puede probar a mano (y cómo se probó)

Algunos escenarios necesitan muchas peticiones al mismo tiempo. Se probaron con pruebas automáticas, superadas con PHP 8.1 y PHP 8.5:

Además: restricciones CHECK (aforo > 0, disponibles <= aforo, nombre no vacío), índices para la lista de obras y para contar las entradas de cada comprador, motor InnoDB (transacciones) y utf8mb4 para acentos y eñes.

Cómo se registra una venta sin vender de más

Todo ocurre dentro de una transacción:

-- 1. Descontar la entrada solo si todavía hay y la obra no ha empezado.
UPDATE OBRA SET disponibles = disponibles - 1
 WHERE cod_obra = ? AND disponibles > 0 AND fecha_obra > NOW();

-- 2. Si no modificó la fila: "Entradas no disponibles" y no se registra nada.
-- 3. Contar las entradas que ya tiene ese comprador para la obra (máximo 4).
SELECT COUNT(*) FROM VENTAS WHERE cod_obra = ? AND comprador = ? FOR UPDATE;

-- 4. Registrar la venta y confirmar. LAST_INSERT_ID() es el número de entrada.
INSERT INTO VENTAS (cod_obra, comprador, fecha_compra) VALUES (?, ?, NOW());
COMMIT;

El UPDATE bloquea la fila de la obra hasta el COMMIT, así que las compras simultáneas de una misma obra se atienden de a una: la última entrada se vende una sola vez y el límite por persona no se puede saltar comprando desde varios navegadores a la vez. Si MySQL aborta la transacción por un bloqueo (mucha carga), la compra se reintenta sola hasta 3 veces; como la transacción fallida se deshace completa, reintentar nunca duplica una venta.

Seguridad y prevención de errores

RiesgoCómo se previene
Errores técnicos en pantallaTodo error se registra en el log y el usuario ve una página amigable, también si MySQL no responde. Los avisos de PHP se tratan como errores para no seguir en un estado inconsistente.
Inyección SQLTodas las consultas usan sentencias preparadas (PDO, sin emulación).
XSSTodo lo que se muestra pasa por htmlspecialchars; además, la política de seguridad de contenido (CSP) prohíbe ejecutar scripts.
Compra duplicada (doble clic, F5, Atrás)Cada formulario lleva un token de un solo uso; después de comprar se redirige a la confirmación (POST/Redirect/GET).
CSRF (compras desde otro sitio)El mismo token, más la cookie SameSite=Lax.
Bots que compran todas las entradasMáximo 4 entradas por identificador y obra (en la misma transacción de la venta), máximo 20 compras por IP en una hora y, en Docker, límite de solicitudes por segundo en Nginx.
Ver o adivinar entradas ajenasLa confirmación solo muestra las ventas de esa sesión. Desde otro navegador se necesitan el número y el identificador, con un máximo de 10 consultas por IP cada 15 minutos.
Descarga de archivos internosBloqueo en la configuración del servidor web (sección 5) y, en Apache, también con .htaccess.
Robo de la cookie de sesiónCookie HttpOnly y SameSite=Lax; Secure cuando el visitante llega por HTTPS, también detrás de un proxy o balanceador.
Clickjacking, rastreo de tipos, cachéEncabezados X-Frame-Options, X-Content-Type-Options, Referrer-Policy y Cache-Control: no-store.
Zona horariaLa regla «fecha mayor que la actual» la evalúa MySQL con NOW(), no PHP.

Alcance de la protección contra bots: los límites frenan a un script que compra desde una misma conexión o con un mismo identificador. Un ataque distribuido (miles de IP e identificadores inventados) solo se detiene verificando la identidad del comprador, con cuentas de usuario, pago o un CAPTCHA, que quedan fuera de lo que pide el enunciado.
