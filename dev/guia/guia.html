2. Requisitos

ComponenteRequisito
SistemaLinux. Probado en Ubuntu 24.04; sirve cualquier distribución con Docker.
DockerDocker Engine 24 o superior con Docker Compose v2 (comando docker compose). Probado con Docker 29. Si no está instalado, el instalador ofrece instalarlo.
Recursos1 GB de RAM libre, 2 GB de disco y acceso a internet para descargar las imágenes.
Solo para un MySQL existenteMySQL 8.0.16 o superior, o MariaDB 10.3 o superior, y un usuario que pueda crear bases y usuarios (por ejemplo, root).

¿Por qué MySQL 8.0.16? La base usa restricciones CHECK (por ejemplo, disponibles <= aforo). Las versiones anteriores las aceptan pero no las aplican. Si su servidor es más antiguo, el instalador lo avisa.

3. Instalación

1
Copiar el ZIP al servidor y descomprimirlo
scp teatro-v1.3.zip usuario@IP_DEL_SERVIDOR:~
ssh usuario@IP_DEL_SERVIDOR
sudo apt install -y unzip          # si no lo tiene
unzip teatro-v1.3.zip
cd teatro
2
Ejecutar el instalador
sudo ./instalar.sh

Muestra este menú:

Teatro · Instalación con Docker

  1) Instalar con un MySQL nuevo, en Docker (recomendado: no necesita nada más)
  2) Instalar usando un MySQL que ya existe (pide sus credenciales)
  3) Ver el estado
  4) Desinstalar
  0) Salir
Opción [1]:

Entre corchetes aparece la respuesta por defecto, que se acepta con Enter. Si el instalador detecta un MySQL en el servidor, lo indica encima del menú.

3
Abrir la aplicación

Al terminar, el instalador comprueba que la aplicación responde y muestra su dirección:

✓ Teatro está funcionando (MySQL en Docker).

   Dirección:      http://203.0.113.10:8080/
   Configuración:  .env (permisos 600, contiene las claves)
   Estado y logs:  docker compose ps · docker compose logs php
   Este menú:      ./instalar.sh

Resultado esperado: la página «Obras disponibles» con 5 obras.

Si hay un cortafuegos, abra el puerto (sudo ufw allow 8080/tcp).

3.1 Opción 1: MySQL nuevo en Docker

Solo pregunta dos cosas, y basta con pulsar Enter en ambas:

PreguntaRespuesta
Puerto web [8080]El puerto donde se abrirá la aplicación. Escriba 127.0.0.1:8080 si va a poner un proxy con HTTPS delante (sección 3.3).
Zona horaria de MySQL [-06:00]Decide qué obras ya pasaron. Formato ±HH:MM, por ejemplo -05:00.

Después levanta tres contenedores: Nginx, PHP 8.5 y MySQL 8.4. MySQL crea la base TEATRO, importa database/teatro.sql y crea el usuario teatro_app con una clave aleatoria de 48 caracteres. La primera vez tarda unos minutos, porque descarga las imágenes.

Si se vuelve a elegir la opción 1 con Teatro ya instalado, el instalador pregunta si se quiere actualizar y conservar los datos o empezar de cero con los datos de ejemplo.

3.2 Opción 2: MySQL que ya existe

PreguntaRespuesta
¿Dónde está MySQL?1 si está instalado en este mismo servidor: se conecta por su socket, sin abrirlo a la red ni cambiar su configuración. El instalador busca el socket solo (/var/run/mysqld/mysqld.sock).
2 si está en otro servidor, o publicado en un puerto: pide la IP o el nombre y el puerto.
Usuario y contraseñaUn usuario que pueda crear bases y usuarios, por ejemplo root. En Ubuntu, el root de MySQL suele no tener contraseña: pulse Enter. Estas credenciales no se guardan. Si son incorrectas, muestra el error de MySQL y deja reintentar.
Si la base TEATRO ya existePermite conservarla con sus datos o reemplazarla por los datos de ejemplo.
¿Crear el usuario teatro_app? [S/n]Recomendado: la aplicación usa un usuario que solo tiene SELECT, INSERT, UPDATE y DELETE sobre TEATRO, con una clave aleatoria.
Puerto web [8080]Igual que en la opción 1.

Antes de levantar los contenedores, comprueba que la aplicación puede leer la base con el usuario que va a usar. En este modo solo corren Nginx y PHP.

3.3 HTTPS con un dominio (opcional)

  1. Apuntar el dominio (por ejemplo, teatro.ejemplo.com) a la IP del servidor.
  2. Ejecutar sudo ./instalar.sh y responder 127.0.0.1:8080 como puerto, para que solo se acceda desde el propio servidor.
  3. Instalar Caddy (sudo apt install -y caddy), que obtiene y renueva el certificado solo, y dejar en /etc/caddy/Caddyfile:
teatro.ejemplo.com {
    reverse_proxy 127.0.0.1:8080
}

Después, sudo systemctl reload caddy. La aplicación reconoce el HTTPS por el encabezado X-Forwarded-Proto y marca la cookie como Secure. Nginx toma la IP real del visitante de X-Forwarded-For, para que los límites por IP se apliquen a cada visitante y no al proxy.

6. Solución de problemas

SíntomaSolución
«Su usuario no tiene permiso para usar Docker»Ejecute sudo ./instalar.sh.
«Permiso denegado» al ejecutar ./instalar.shUse sudo bash instalar.sh. Pasa si el ZIP se descomprimió con una herramienta que no conserva los permisos.
«Docker no está en ejecución»sudo systemctl start docker
«El puerto … ya está en uso»El instalador pide otro puerto.
Opción 2: «Access denied»Usuario o contraseña incorrectos, o el usuario no puede conectarse desde Docker. Si MySQL está en el mismo servidor, elija «Instalado en este mismo servidor»: se conecta por el socket, como un cliente local.
Opción 2: «Can't connect» con un MySQL en otro servidorEse MySQL debe aceptar conexiones de esta máquina (bind-address, cortafuegos y un usuario permitido desde esta IP).
«Servicio no disponible»La aplicación no llega a MySQL. El detalle está en sudo docker compose logs php.
«No hay obras disponibles»Las fechas de los datos de ejemplo ya pasaron: sudo ./instalar.sh → 1 → 2.
«Demasiadas compras» o «Demasiadas consultas»Es la protección contra compras masivas. Espere o suba el límite (sección 5).
docker compose up dice «Falta la configuración»Es a propósito: no hay claves por defecto. Ejecute sudo ./instalar.sh.

7. Cómo funciona por dentro

Arquitectura

Visitante ──▶ web (Nginx)  ──▶ php (PHP 8.5-FPM) ──▶ db (MySQL 8.4, opción 1)
             puerto 8080        solo lectura          red interna, sin puertos publicados
             4 páginas + CSS                          o el MySQL existente (opción 2)

Cómo se registra una venta sin vender de más

-- Todo dentro de una transacción.
UPDATE OBRA SET disponibles = disponibles - 1
 WHERE cod_obra = ? AND disponibles > 0 AND fecha_obra > NOW();   -- si no cambia nada: agotada
SELECT COUNT(*) FROM VENTAS WHERE cod_obra = ? AND comprador = ? FOR UPDATE;   -- máximo 4
INSERT INTO VENTAS (cod_obra, comprador, fecha_compra) VALUES (?, ?, NOW());
COMMIT;   -- LAST_INSERT_ID() es el número de entrada

El UPDATE bloquea la fila de la obra hasta el COMMIT, así que las compras simultáneas de una obra se atienden de a una. Si MySQL aborta la transacción por un bloqueo, la compra se reintenta sola; como la transacción fallida se deshace completa, nunca se duplica una venta.

Seguridad

RiesgoCómo se previene
Inyección SQL y XSSSentencias preparadas; escape de toda la salida y una CSP que prohíbe ejecutar scripts.
Compras duplicadas y CSRFToken de un solo uso por formulario, POST/Redirect/GET y cookie SameSite=Lax.
Bots que compran todoMáximo por persona y obra, por IP y por segundo en Nginx.
Ver entradas ajenasLa confirmación solo muestra las ventas de la sesión; desde otro navegador se piden el número y el identificador.
Archivos internos y clavesNginx solo publica las 4 páginas y los estilos. .env con permisos 600. Sin claves por defecto: sin .env, Docker no arranca. Las credenciales de administrador de la opción 2 no se guardan.
Acceso a la baseUsuario teatro_app con permisos mínimos. En la opción 1, MySQL está en una red interna sin puertos publicados y su root tiene una clave aleatoria.
Errores técnicos en pantallaEl usuario ve una página amigable; el detalle va al log, sin contraseñas.
ContenedoresSistema de archivos de solo lectura y no-new-privileges.

Alcance de la protección contra bots: los límites frenan a un script que compra desde una misma conexión o con un mismo identificador. Un ataque distribuido solo se detiene verificando la identidad del comprador (cuentas, pago o CAPTCHA), que quedan fuera del enunciado.
